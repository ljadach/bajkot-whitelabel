== Przegląd

Intake flow to konwersacyjny proces zbierania informacji o użytkowniku poprzez chat z agentem AI.
Użytkownik odpowiada na pytania, a system buduje profil XML który jest źródłem prawdy.

=== Kluczowe komponenty

[cols="1,2,3"]
|===
|Warstwa |Komponent |Odpowiedzialność

|Frontend
|`ChatStep.tsx`
|Orchestracja UI, zarządzanie lokalnym stanem

|Frontend
|`useChatStream.ts`
|Hook do streamingu HTTP, parsowanie odpowiedzi

|Backend
|`streaming.ts`
|HTTP Action, wywołanie LLM, streaming do przeglądarki

|Backend
|`profiles.ts`
|Mutacje do zapisu profilu i historii czatu

|Database
|`userProfiles`
|Tabela z profilem, historią czatu, profileXml
|===

== Format odpowiedzi LLM

LLM zwraca tekst w formacie z delimiterem `---JSON---`:

[source]
----
Great! **What tools do you use?** ✨
---JSON---
{"widget":{"type":"multi-select","options":["ChatGPT","Claude"]},"profileXml":"<profile>...</profile>","complete":false}
----

=== Struktura JSON

[source,json]
----
{
  "widget": {
    "type": "multi-select",       // lub "single-select", "likert", "free-text"
    "options": ["Option 1", ...]  // tylko dla select/likert
  },
  "profileXml": "<profile>...</profile>",  // zaktualizowany profil
  "complete": false               // true gdy intake zakończony
}
----

=== Typy widgetów

[cols="1,2,2"]
|===
|Typ |Opis |Rendering

|`multi-select`
|Wielokrotny wybór
|Checkboxy lub pill buttons

|`single-select`
|Pojedynczy wybór
|Radio buttons

|`likert`
|Skala 1-5
|5 przycisków numerycznych

|`free-text`
|Wolny tekst
|Textarea
|===

=== Kluczowe aspekty

1. **Non-blocking streaming**: `void (async () => {...})()` - nie czekamy na streaming, zwracamy Response od razu
2. **Lifecycle Convex**: HTTP Action kończy się gdy `writer.close()` zostanie wywołane
3. **Logowanie przed close**: `storeLlmLog()` MUSI być wywołane PRZED `writer.close()`

=== Walidacja i parsowanie

[source,typescript]
----
// streamParser.ts

extractStreamingMessage(partialText)
    │
    ├── indexOf("---JSON---") === -1
    │       └── return partialText.trim()  // still streaming
    │
    └── indexOf("---JSON---") >= 0
            └── return text before delimiter

parseStreamedIntakeResponse(fullText)
    │
    ├── no delimiter → return null
    │
    ├── no JSON after delimiter → return null
    │
    ├── JSON.parse fails → return null
    │
    └── success → return {message, widget, profileXml, complete}

== Podsumowanie

Intake flow to streaming-first architektura gdzie:

1. **Źródło prawdy** = `userProfiles.profileXml` w bazie
2. **Streaming** = HTTP Action → TransformStream → Browser
3. **Aktualizacje** = Po każdej odpowiedzi użytkownika cała historia + nowy profileXml są zapisywane
4. **LLM widzi** = Całą historię czatu + aktualny profil przy każdym pytaniu
5. **Fallback** = Hardcoded odpowiedź gdy LLM zawiedzie

Architektura optymalizuje UX (streaming) przy zachowaniu prostoty (brak persistence layer dla streamu, bezpośredni LLM→Browser).
