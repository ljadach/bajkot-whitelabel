# 2026-04-23 — Stripe billing import z aitutorc

## Problem

Bajkot potrzebuje płatności. Aitutorc ma działającą integrację Stripe na branchu `codex/stripe-billing-v1` (jeden commit `53d9a10`, później zmergowany i zrevertowany w main). Zamiast pisać od zera — przeniesienie tego, co generic, i potraktowanie reszty jako wzorca do adaptacji.

## Co zostało przeniesione 1:1

Backend Convex — wszystko trzyma się na `subscriptions` table + Clerk `identity.subject`:

- `convex/stripe.ts` — Node action: `createCheckoutSession`, `createCustomerPortalSession`, `verifyWebhookEvent`. Tryb `subscription`, automatic tax, metadata `clerkUserId`. Return URL z `?checkout=success|cancelled`.
- `convex/stripeHttp.ts` — HTTP action dla webhooka. Dyskryminuje błędy podpisu (400, Stripe nie retry'uje) od transientów (500, retry).
- `convex/billing.ts` — internal queries dla state Stripe customer, internal mutation `syncSubscriptionFromStripe` z webhooka, public query `getBillingSummary`. Odchudzone vs aitutorc: bez `getAccessState` i `unlockFreeModule` (te zależą od `courses`/`moduleUnlocks`, których bajkot nie ma).
- `convex/lib/billing.ts` — helpery (`getLatestSubscriptionForUser`, `getSubscriptionByStripeSubscriptionId`, `isUserPro`, `ACTIVE_SUBSCRIPTION_STATUSES`, validator).
- `convex/schema.ts` — dodana tabela `subscriptions` (clerkUserId, stripeCustomerId, stripeSubscriptionId, stripePriceId, status, cancelAtPeriodEnd, currentPeriodEnd, timestamps) z trzema indeksami.
- `convex/http.ts` — route `POST /stripe/webhook` → `receiveWebhook`.
- `package.json` — `stripe@^20.4.1`.

## Co zostało jako referencja (do adaptacji)

W `docs/stripe-import-from-aitutorc/` siedzą oryginały, których 1:1 nie da się odpalić w bajkot, bo zależą od domain modelu aitutorc (kursy + module unlocks):

- `aitutorc-billing.ts` — pełna logika `getAccessState` + `unlockFreeModule` (freemium 2 unlock + paywall na resztę modułów).
- `aitutorc-lib-billing.ts` — `getBillingAccessState`, `getUnlockedPageIndexes`, `canUserAccessPage` z Iden `courses`/`moduleUnlocks`.
- `components-billing/{FreeUnlockPrompt,LockedModuleView,UpgradePrompt}.tsx` — gotowe komponenty paywallu (i18n via react-i18next, klasy z aitutorc design system).
- `useCheckoutReturn.ts` — hook do toast/cleanup po powrocie z Checkout.
- `stripe-integration-plan.md` — pełny plan integracji (757 linii — read first).

`docs/stripe-setup-checklist.md` poszedł bezpośrednio do `docs/` (jest generic, instrukcja konfiguracji konta Stripe i webhooka).

## Decyzja modelu biznesowego — open

Aitutorc: subskrypcja Pro + 2 darmowe module unlocks per kurs. Bajkot: dziś `bookOrders` ma `paymentStatus: 'pending' | 'completed' | 'failed'` i `stripeSessionId` — czyli implicit one-shot per książka.

Dwie ścieżki do wyboru:

1. **One-shot per książka** — `mode: 'payment'` w Checkout, attach `bookOrders._id` jako `client_reference_id`/`metadata.bookOrderId`, webhook `checkout.session.completed` ustawia `paymentStatus = 'completed'`. Nie potrzeba `subscriptions` table — można ją zostawić nieużywaną na potem.
2. **Subskrypcja** — bieżący kod działa, trzeba dodać UX (LockedModuleView/UpgradePrompt). Nadpisuje per-book payment.
3. **Hybryda** — subskrypcja Pro daje X książek/miesiąc, jednorazowy zakup poza limitem.

Zostawione do decyzji w PR. Default w skopiowanym `stripe.ts` to `mode: 'subscription'` — pod ścieżkę 2 i 3.

## Trade-offs

- Zostawiona `subscriptions` table mimo niepewności modelu — koszt schema'y zerowy, jeśli pójdziemy w one-shot, table stays empty. Jeśli usuniemy ją z `schema.ts`, trzeba też wyrzucić `billing.ts`/`lib/billing.ts`/`stripe.ts`/`stripeHttp.ts` (kaskada).
- `convex/stripe.ts` używa `Doc<'subscriptions'>['status']` w `NormalizedSubscriptionStatus` — typecheck wywali się, dopóki schema nie zaaplikuje `subscriptions` (czyli `convex dev --once` musi się przebiec po `npm install`).
- Webhook secret jest osobny per środowisko (dev / prod). `stripe listen` w dev daje `whsec_...` na sesję CLI; prod ma stały sekret z dashboardu.
- Komponenty paywallu w `docs/stripe-import-from-aitutorc/components-billing/` używają `useTranslation('plan')` — w bajkot trzeba albo przepiąć na bajkot namespace, albo zostawić jako wzorzec UX i napisać własne.
