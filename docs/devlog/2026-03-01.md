## Fix: zapętlony intake po refaktorze promptów (a53a144)

Refaktor promptów z ALL_CAPS na Markdown headers (commit a53a144) złamał intake chat. Pytania zapętlały się w nieskończoność, przepaliliśmy ~$20 na LLM calls.

**Root cause:** W nowym prompcie example JSON został owinięty w ` ```json ``` ` code fence. LLM kopiował ten wzorzec i owijał swój output w backticki. Parser (`streamParser.ts`) robił `JSON.parse()` na tekście zaczynającym się od ` ```json ` → crash → `complete` nigdy nie było `true` → pętla.

**Fix trójwarstwowy:**
1. Usunięcie code fence z example w `INTAKE_SYSTEM_FALLBACK` (root cause).
2. Defensywny strip backtików w `streamParser.ts` przed `JSON.parse()` (defense in depth).
3. Hard limit `MAX_INTAKE_QUESTIONS = 30` w trzech warstwach: `streaming.ts`, `ai.ts` (backend), `ChatStep.tsx` (frontend safety net). Po przekroczeniu limitu — force `complete: true` z WARN logiem.

Dodatkowe cleanup po code review: wyciągnięcie `currentProfileXml`/`language` przed guard w ai.ts, i18n force-complete message w obu backend paths.

## Usunięcie bias na prompt templating

Generowane podręczniki wymuszały prezentowanie promptów w sztywnym formacie 5-częściowym (Role/Context/Task/Format/Constraints). Cargo cult z ery GPT-3.5 — w 2026 modele rozumieją naturalny język, a szablonowe podejście jest nieadekwatne zwłaszcza dla orkiestracji (agenci, MCP, tool use).

Trzy zmiany:
1. **`editorialGuide.ts`** — usunięta sekcja "Prompt Template Format" z 5-part structure i example template. Zastąpiona wytycznymi: naturalne prompty, dopasowanie formy do tematu (prompt, system instruction, tool config, agent workflow), placeholders tylko gdy uzasadnione.
2. **`courseFallbacks.ts`** (oba warianty: standard + video-enhanced) — `MANDATORY: prompt template with {PLACEHOLDERS}` → `practical example of interacting with AI (concrete prompt, tool config, or agent setup)`.

Efekt: handbooki mogą teraz uczyć interakcji z AI w formie adekwatnej do tematu, zamiast wpychać wszystko w ten sam formularz.

Architektura zero-CI: Vercel build command robi `npx convex deploy --cmd 'npm run build' --cmd-url-env-var-name VITE_CONVEX_URL`. Push → Vercel ciągnie kod → deployuje Convex backend → buduje frontend → serwuje. Bez GitHub Actions.

Gotcha: Convex blokuje production deploy key w non-production Vercel build environment. Fix: ustawić Production Branch na `staging` w Vercel project. Trzeba też `ALLOWED_ORIGIN` i `OPENROUTER_API_KEY` w Convex env vars dla stagingu.
