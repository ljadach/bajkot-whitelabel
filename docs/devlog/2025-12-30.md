# 2025-12-30

## Refaktor streamingu intake chat

Przepisanie streamingu intake na wzorzec z artykułu Convex "AI Chat with HTTP Streaming".

### Problem

Poprzednia implementacja używała skomplikowanego formatu z XML tagami:
```
<streaming_message>Pytanie...</streaming_message>
<structured_data>{"widget":...}</structured_data>
```

LLM czasem gubił format tagów. Parsing wymagał regex i był kruchy.

### Rozwiązanie

Uproszczony format z delimiterem:
```
Pytanie tutaj...
---JSON---
{"widget":{"type":"multi-select","options":[...]},"profileXml":"...","complete":false}
```

**Zmiany:**
- `convex/lib/prompts.ts` - nowy format w `IntakeXmlStreamingSystem`
- `convex/lib/streamParser.ts` - z 112 do 87 linii, prosty `indexOf` zamiast regex
- `convex/streaming.ts` - HTTP action z TransformStream
- `src/hooks/useChatStream.ts` - hook do obsługi streamu
- `src/components/steps/ChatStep.tsx` - uproszczony, używa hooka

### Dodanie logowania LLM do intake

Intake streaming nie miał logów - trudne debugowanie. Dodane:
- Langfuse span tracking (`startActiveObservation`)
- Zapis do tabeli `llmLogs` via `internal.llmLogs.storeLlmLog`

**Bug:** Logi się nie zapisywały bo `storeLlmLog()` było po `writer.close()`. Convex kończy HTTP action gdy writer się zamknie.

**Fix:** `storeLlmLog()` PRZED `writer.close()`.

### Architektura streamingu (Convex pattern)

```
Browser                    HTTP Action                  LLM
   |                           |                         |
   |---POST /stream-question-->|                         |
   |                           |---streamText()--------->|
   |<---Response(readable)-----|                         |
   |                           |                         |
   |<========chunks============|<====chunks==============|
   |                           |                         |
   |                           |--storeLlmLog()          |
   |                           |--writer.close()         |
   |<===stream ends============|                         |
```

Kluczowe: `void (async () => {...})()` - nie czekamy na streaming, zwracamy Response od razu. Convex czeka na `writer.close()`.

## Potencjalne usprawnienia

### Pilne
1. **Brak retry dla intake** - jeśli LLM zawiedzie, user widzi fallback. Brak auto-retry jak w `chatJsonWithRetries`.
2. **Prompt w Langfuse** - `intake-streaming-system` trzeba zaktualizować w Langfuse (teraz używa fallbacka).

### Nice to have
1. **Periodic DB saves** - artykuł Convex zapisuje do DB co zdanie (delimiter). Daje innym userom partial updates. U nas nie potrzebne (single user flow), ale warto rozważyć.
2. **Stream cancellation** - user może zamknąć stronę w trakcie. Hook ma AbortController ale nie ma cleanup po stronie serwera.
3. **Rate limiting na HTTP action** - obecnie tylko na mutations.

### Tech debt
1. **Duży bundle** - 783KB (gzip 236KB). Trzeba code splitting.
2. **`_generated/` w git** - nie powinno być commitowane.

## Sesja 2: UX improvements

### Ctrl+Enter w chacie
Dodany skrót klawiszowy `Ctrl+Enter` / `Cmd+Enter` do wysyłania odpowiedzi w chat widget. Hint widoczny przy przycisku Next.

```tsx
const handleKeyDown = (e: React.KeyboardEvent) => {
  if ((e.ctrlKey || e.metaKey) && e.key === 'Enter' && readyToSubmit) {
    e.preventDefault();
    onSubmit();
  }
};
```

### Połączenie Summary + Assessment

**Problem:** Dwa osobne kroki (summary → assessment) - user musiał kliknąć "Continue" i czekać na generację.

**Rozwiązanie:** Jeden ekran z:
- Profile Summary (górna karta)
- Assessment (dolna karta, auto-generuje się przy mount)

User czyta summary podczas gdy assessment się generuje w tle.

**Zmiany:**
- `SummaryStep.tsx` - połączony z funkcjonalnością AssessmentStep
- `TutorFlow.tsx` - `assessment` step mapuje do SummaryStep
- `App.tsx` - `assessment: '/summary'` dla backward compatibility
- `AssessmentStep.tsx` - pozostaje w repo, nieużywany

**Flow teraz:**
```
verification → summary (profile + auto-assessment) → plan
```

### ReactMarkdown zamiast dangerouslySetInnerHTML

Zmiana renderowania markdown w assessment i plan cards:
- Było: `dangerouslySetInnerHTML={{ __html: renderMarkdown(text) }}`
- Jest: `<ReactMarkdown components={...}>{text}</ReactMarkdown>`

Bezpieczniejsze + konsystentne style z HandbookContent w course-preview.

### Markdown w kartach Training Plan

Dodane formatowanie markdown do OutlineCard:
- title, summary, teasers, cta, details
- Kompaktowe komponenty (p → span) żeby nie psuć layoutu
