## Post-launch fixes (bundle)

Cezary jechał po produkcji, znalazł 4 rzeczy. Wszystko w jednym PR żeby było jednym deploy'em.

### #5 (critical) — `createLandingCheckoutSession` "Invalid access token"

Prod log: `Uncaught Error: Invalid access token at stripe.ts:122`. User klika "Odblokuj PDF" na `/landing/book/:id/result` → action wymaga `accessToken === LANDING_ACCESS_TOKEN`, którego user nigdy nie wpisał (token miał tylko ten kto wszedł z `?token=` URL).

Fix: usunięty token check z `createLandingCheckoutSession`. Argumentacja — token gate'uje _intake_ (`startLandingOrder`), tam burn'uje się budżet Gemini. Checkout sam w sobie kosztuje $0 (Stripe API call). Ownership check (`clerkUserId === LANDING_USER_ID`) wystarcza, a frontend `LandingBookResult.tsx` już nie wysyła `accessToken`.

### #1 — bypass UI ukryty dla non-admin

`OrderPreview` renderował dashed amber "Tryb deweloperski" box z `skipStripe / skipQa / fastImage` checkboxami dla każdego visitora. Plus default `skipStripe=true, skipQa=true, fastImage=false` w `LandingOrderFlow` i `AuthOrderFlow` — każdy mógł kliknąć "Continue" i przepłynąć pipeline bez płatności.

Trzy zmiany:

1. `OrderPreview` — diagnostic box renderowany tylko gdy `isAdmin`.
2. Frontend defaults: `skipStripe=false, skipQa=false, fastImage=true` (fast image domyślnie ON dla prod intake — Cezary wprost o to prosi, bo to cheap path).
3. Backend gate:
   - `startOrder` — `isAdminRole(ctx)` decyduje czy honorować flagi. Non-admin → flagi discarded, `fastImage` forced ON.
   - `startLandingOrder` — landing user nigdy nie jest adminem, więc flagi zawsze discarded, hard-coded `fastImage=true`.

Defence in depth: nawet jak ktoś pomieszany w devtools wyśle `skipStripe=true`, backend zignoruje.

### #3 — 7-stron preview + copy bez "pierwsze 3 strony"

`bookComposer.ts` slice'uje `expandedSequence` na preview PDF. Było 3 strony — Cezary chce 7 (większy teaser, bajka i tak ma ~12-15 stron, więc to wciąż pół).

Plus copy fix:

- `paywall.heading`: `"„{{bookTitle}}\" — pierwsze 3 strony"` → `"„{{bookTitle}}\""` (sam tytuł)
- `paywall.headingFallback`: `"Twoja bajka jest gotowa — zobacz pierwsze 3 strony"` → `"Twoja bajka jest gotowa"`

Zostaje jeden problem dla legacy orderów — preview PDF z 3 stronami zapisany w `previewPdfStorageId` zostaje 3-stronicowy. Świadomie nie regeneruję, bo to nieobsługiwany backfill na produkcji i te ordery prawdopodobnie i tak już za-paid (po payment user pobiera full PDF, preview przestaje mieć znaczenie).

### #4 — responsive flipbook

Książka 720×720px wciskała się w `max-w-3xl` (768px) container z `p-8` padding → wychodziła poza box. `BookPdfFlipbook` dostał `ResizeObserver` na parent, width = `clamp(280, parentWidth, 640)`. Height tracks width (1:1, bo composer emituje square PDF). Działa płynnie na resize.
