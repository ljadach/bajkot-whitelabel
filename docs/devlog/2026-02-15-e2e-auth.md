# 2026-02-15 — E2E auth persistence fix + porządki w docs

## Problem

Testy e2e za każdym razem wymagały logowania od nowa. `hasFreshSession()` sprawdzał JWT `exp` z cookie `__session` — ale to krótko-żyjący token Clerka (60s TTL), więc zawsze wychodził jako expired. Dodatkowo `global-setup.ts` robił sign-out jeśli widział zalogowanego usera, co niszczyło sesję.

## Rozwiązanie

### Auth persistence

Clerk ma dwa cookie:
- `__session` — JWT, 60s TTL, odnawiany automatycznie na page load
- `__clerk_db_jwt` — opaque token (`dvb_...`), long-lived (tygodnie/miesiące)

Stary kod dekodował `__session` JWT → sprawdzał `exp` → zawsze expired.

Nowy kod: sprawdza pole `expires` na cookie `__clerk_db_jwt` (unix timestamp ustawiany przez Clerka, nie w JWT payload). W naszym przypadku cookie ma `expires: 1802708065` (~2027), więc sesja trzyma się miesiącami.

### Login script (`00-login.spec.ts`)

Stary: otwierał browser, pre-fillował email, czekał na ręczne dokończenie.
Nowy: auto-fill email + hasło z `.env.test`, submit, i czeka tylko na kod weryfikacyjny jeśli Clerk go wymaga.

### Test isolation

`00-login.spec.ts` dodany do `testIgnore` w playwright config — `npm run test:e2e` go pomija. Odpalany jawnie przez `npm run e2e:login`.

### Flow teraz

1. `npm run e2e:login` → auto-fill credentials → wpisz kod → sesja zapisana
2. `npm run test:e2e` → `globalSetup` widzi świeży cookie → skip login → testy jadą
