# 2026-08-19

## „Server Error" na submicie landing order — diagnoza i fix

Zgłoszenie: screenshot od testującej (akwiatkowska) — czerwony box
`[CONVEX A(bookPipeline:startLandingOrder)] [Request ID: 2c466e433d4aa8d4] Server Error`
na kroku checkout. Zero informacji co poprawić.

Logi prod (dashboard, filtr po Request ID, 08:39:39):
`Uncaught Error: problemDetail must be max 500 characters at validateOrderInput`.

Łańcuch przyczyn — trzy dziury, każda osobno by wystarczyła:

1. Textarea „Opisz sytuację" w `OrderWizard.tsx` nie miała `maxLength` —
   jedyne pole tekstowe bez limitu (imię ma 30, zabawka 100, ubiór 120).
   Rodzic opisujący problem dziecka łatwo przebija 500 znaków.
2. `validateOrderInput` rzucał gołe `Error`, które Convex na prodzie
   sanityzuje do „Server Error". Tę samą lekcję odrobiliśmy już przy
   moderacji (`runIntakeGuards` rzuca `ConvexError` z dokładnie takim
   komentarzem) — walidacji długości nikt nie przerobił.
3. `extractErrorMessage` sprawdzał `err.message !== 'Server Error'`, a
   Convex prefiksuje komunikat `[CONVEX A(...)] [Request ID: ...]` — więc
   surowy string przechodził do UI zamiast polskiego fallbacku.

Fix (wszystkie trzy warstwy):

- `OrderWizard.tsx`: `maxLength={SITUATION_MAX}` (500, mirror backendu)
  - licznik znaków widoczny od 80% limitu. Wspólny komponent, więc łata
    jednocześnie flow auth i landing.
- `bookPipeline.ts` `validateOrderInput`: `ConvexError` z polskimi
  komunikatami dla wszystkich trzech limitów.
- `convexErrors.ts`: `includes('Server Error')` zamiast porównania —
  przyszłe niezmapowane błędy pokażą generyczny polski komunikat, nie
  surowy dump Convexa.

Trade-off: `maxLength` ucina twardo bez komunikatu „dlaczego nie mogę
pisać dalej" — licznik od 400 znaków ma to komunikować. Świadomie bez
walidacji inline z błędem: mniej kodu, a backend i tak jest teraz
drugą linią obrony z czytelnym komunikatem.
