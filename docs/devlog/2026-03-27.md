# 2026-03-27 — Pipeline state machine + anti-flicker fix

## Problem

Pipeline miał race condition w parallel tracks. A5 (art direction) i A6 (character design) biegną równolegle po A1, ale oba zapisywały do jednego pola `status`. A6 ustawiał `style_vote`, A5 nadpisywał `art_direction`. Efekt: auto-resolve nie łapał orderów, vote page flickerował, ordery się zawieszały.

## Co zrobiono

### 1. Pipeline state machine (`convex/lib/pipelineStateMachine.ts`)

Nowy moduł z `shouldUpdateStatus(from, to)` — guard na przejścia statusów. Kluczowa reguła: story track (A2-A5) nie może nadpisać image track statusów (`character_design`, `style_vote`) i vice versa. `updateOrderStatus` w helpers teraz czyta aktualny status i sprawdza guard przed zapisem.

### 2. Explicit track completion flags

Dwa nowe pola w `bookOrders`: `storyTrackDone`, `imageTrackDone` (oba `v.optional(v.boolean())`). `checkParallelTracksComplete` używa tych flag zamiast zgadywać z artefaktów (fallback na artefakty dla starych orderów).

Nowa mutacja `setTrackDone` — A5 ustawia `storyTrackDone`, `submitStyleVote` ustawia `imageTrackDone`.

### 3. Anti-flicker frontend

**BookProgress**: Redirect na vote bazujący na `hasStyleVoteImages && !chosenStyle` (nie na polu `status`). `useRef` guard zapobiega re-redirect loops.

**BookStyleVote**: Po submit redirect z `replace: true`. `votedRef` zapobiega ponownemu redirect gdy Convex subscription fire'uje z nowym `chosenStyle`.

### 4. A10 Final QA → programmatic check

Wcześniej A10 robił LLM call z vision (kosztowny, halucynował bo prompt oczekiwał wyrenderowanych stron PDF a dostawał surowe ilustracje). Zamieniony na 6 deterministycznych checków: parsing artefaktów, imię dziecka w tekście, dedykacja, kompletność stron, liczba ilustracji, parent card.

### 5. FAST mode z formularza

Checkbox `skipQaReviews` w sekcji Dev tools na order form. Przepływa przez `startOrder` → `createOrder` → `bookOrders`. Pomija A4, A8, A10.

### 6. Admin navigation

Dashboard → ordery prowadzi do `?tab=orders` w BookBatch. Tab state derived z `searchParams` (single source of truth).

## Trade-offs

- State machine jest opt-in (guard w `updateOrderStatus`). Agenty które wołają `ctx.db.patch` bezpośrednio (admin retry) go omijają — to jest celowe.
- Track flags są optional — backward compatible ze starymi orderami.
- `useRef` guard w BookProgress jest one-shot per mount — jeśli user wraca na progress ręcznie, komponent się remountuje i ref jest reset.
