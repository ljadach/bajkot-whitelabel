# 2026-01-12

## Co zrobiliśmy

Naprawiliśmy stabilność i UX kroku intake (chat). Główne problemy:
1. Dwa przyciski "Continue" na ekranie
2. Ponowne wejście na /chat wywoływało LLM nawet gdy rozmowa była zakończona
3. Edycja odpowiedzi generowała nowe pytanie zamiast przywrócić oryginalne
4. Wiadomość pożegnalna nie była wyświetlana/persystowana

### Zmiany

**Schema (`convex/schema.ts`):**
- Dodane pole `intakeComplete: v.optional(v.boolean())` do `userProfiles`

**Backend (`convex/profiles.ts`):**
- `createOrUpdateProfile` - obsługuje nowe pole `intakeComplete`
- `resetProfile` - resetuje `intakeComplete: undefined`

**Prompty (`convex/lib/prompts.ts`):**
- Zmieniona semantyka flagi `complete` w intake prompts
- Stara logika: `complete: true` gdy pola wypełnione
- Nowa logika: `complete: true` TYLKO gdy LLM mówi pożegnanie (bez pytania)
- Dodana reguła: `NEVER set complete=true while asking a question`

**Hook `useChatStream.ts`:**
- Dodana funkcja `setQuestion()` do ręcznego ustawiania pytania (dla edit mode)
- Zmiana logiki: jeśli `complete: true`, zaufaj fladze i ignoruj widget
- Wcześniej: jeśli jest widget → to pytanie (ignorowano complete)
- Teraz: jeśli `complete: true` → to pożegnanie (ignoruj widget)

**ChatStep (`src/components/steps/ChatStep.tsx`):**
- Sprawdzanie `profile?.intakeComplete` przed wywołaniem LLM
- Jeśli intake complete w DB → skip LLM call, ustaw stan lokalny
- Wiadomość pożegnalna dodawana do `localHistory` i persystowana
- Usunięty stan `completionMessage` - wszystko w historii
- Edit answer: przywraca oryginalne pytanie z historii (bez LLM call)
- ChatWidget ukryty gdy `isIntakeComplete === true`

**ChatWidget (`src/components/chat/ChatWidget.tsx`):**
- Przycisk "Continue" → ikona strzałki w górę (jak OpenAI/Claude)
- Okrągły button 36x36px

**Debug Panel (`src/components/debug/DebugTabApp.tsx`):**
- Pokazuje status intake: zielony badge "Complete" lub żółty "In progress"

## Flow po zmianach

| Scenariusz | Zachowanie |
|------------|------------|
| Pierwsze wejście na /chat | LLM generuje pytanie |
| Powrót na /chat (intake in progress) | LLM generuje kolejne pytanie |
| Powrót na /chat (intake complete) | **Bez LLM call** - historia + ContinueBar |
| LLM mówi pożegnanie | Dodaje do historii, ustawia flagę w DB |
| Edit answer | Przywraca oryginalne pytanie z historii (bez LLM) |
| Reset profile | `intakeComplete: undefined`, nowa rozmowa |

## Kluczowe decyzje

1. **Flaga `intakeComplete` w DB** - źródło prawdy o stanie rozmowy, nie lokalny stan
2. **Wiadomość pożegnalna w historii** - nie osobny stan, persystuje między sesjami
3. **Edit bez LLM** - `setQuestion()` pozwala ustawić pytanie ręcznie z historii
4. **Zaufaj `complete: true`** - jeśli LLM mówi że skończył, to skończył (nawet jeśli wysłał widget)

## Obserwacje

1. **Race condition z useEffect** - po `void updateProfile({ intakeComplete: true })` profile się aktualizuje, triggeruje useEffect, który nadpisywał stan lokalny. Rozwiązanie: wszystko w historii, nie w osobnym stanie.

2. **LLM nie jest deterministyczny** - edit answer wywoływał LLM który generował INNE pytanie. Rozwiązanie: przywracamy oryginalne pytanie z historii.

3. **Widget vs complete** - LLM czasem wysyłał `complete: true` z widgetem (co było sprzeczne). Nowa logika: `complete` ma priorytet.

## Refaktoryzacja backendu - uproszczenia

Przeanalizowano backend pod kątem duplikacji i zbędnej złożoności. Zaimplementowano 10/10 propozycji uproszczeń.

### Zmiany

**Usunięte pliki:**
- `convex/router.ts` - połączone z `http.ts`
- `convex/payments.ts` - pusty placeholder

**Nowe pliki:**
- `convex/lib/utils.ts` - wspólny `randomHex()`
- `convex/lib/actionHelpers.ts` - `prepareAuthenticatedLlmAction()` dla akcji LLM
- `convex/lib/dbHelpers.ts` - `getProfileByClerkUserId()`, `getAuthenticatedProfile()`, `getOrgManagerOrAdminMembership()`

**Ujednolicone walidatory:**
- `chatMessageValidator` - usunięte 3 inline definicje w `ai.ts`, teraz import z `lib/chatMessage.ts`

**Zmniejszone boilerplate w akcjach LLM:**
- `ai.ts`: 5 akcji używa teraz `prepareAuthenticatedLlmAction()`
- `quickTipAi.ts`, `exerciseAi.ts`: również używają helpera
- ~60 linii boilerplate usunięte (auth + rate limit + config w każdej akcji)

**Uproszczone query profilu:**
- `getProfileByClerkUserId()` zastąpił ~20 powtórzonych bloków query
- Naprawiono typowanie `updateStreak` (był `any`)

**Wyciągnięta logika kasowania danych:**
- `deleteCourseDocumentsAndExercises()` - wspólna dla resetProfile i deleteAccount
- `deleteUserProgressData()` - z parametrem mode ('reset' | 'delete')

**Helper uprawnień organizacji:**
- `getOrgManagerOrAdminMembership()` - zastępuje powtarzający się pattern w 5 miejscach

**Optymalizacja N+1 queries (`convex/teamProgress.ts`):**
- `getTeamDashboard`: zamiast N sekwencyjnych queries, teraz 3 równoległe batche (userPoints, profiles, chapterProgress)
- `getTeamMemberProgress`: to samo - 3 równoległe batche + lookup z Map
- `getTeamLeaderboard`: 1 równoległy batch dla userPoints
- Pattern: `Promise.all(memberIds.map(id => query(id)))` + budowanie Map dla lookup

### Obserwacje

1. Convex wymaga pliku `http.ts` dla HTTP routes - nie można go usunąć, ale można połączyć z router.ts
2. `prompts.ts` (re-export) zostawiono - może być używany przez frontend
3. Helper `prepareAuthenticatedLlmAction` musi być w osobnym pliku bo importuje `internal` z generated API

## Infrastruktura E2E z Playwright

Zaimplementowano pełną infrastrukturę testów E2E z Playwright. Real LLM (nie mockowany), happy path + edge cases.

### Struktura

```
e2e/
├── fixtures/test.fixture.ts     # Auth + reset profile przed każdym testem
├── helpers/
│   ├── streaming.ts             # waitForStreamingComplete, waitForContentStable
│   └── test-data.ts             # Sample prompts, default answers
├── pages/
│   ├── chat.page.ts             # ChatPage - answerQuestion(), completeIntakeWithDefaults()
│   ├── verification.page.ts     # VerificationPage - submitPrompt(), waitForScoring()
│   ├── summary.page.ts          # SummaryPage - waitForAssessment()
│   └── plan.page.ts             # PlanPage - waitForOutline(), openModule()
├── tests/
│   ├── happy-path.spec.ts       # Pełny flow: Chat → Verification → Summary → Plan
│   ├── chat.spec.ts             # Chat: streaming, edit, error handling
│   ├── navigation.spec.ts       # Step guards, blocked access
│   └── verification.spec.ts     # Prompt scoring
├── global-setup.ts              # Jednorazowy login do Clerk (storageState)
└── playwright.config.ts         # Konfiguracja
```

### Kluczowe decyzje

1. **Auth via storageState** - jednorazowy login w global-setup.ts, reużywany przez wszystkie testy
2. **Real LLM** - nie mockujemy odpowiedzi, testujemy z prawdziwym API (generous timeouts)
3. **resetProfile przed testami** - izolacja danych między testami
4. **Page Objects** - czysty interfejs do interakcji z UI

### Auto-Fill Self-Play

Zamiast ręcznego odpowiadania na pytania (flaky - różne typy widgetów, różne pytania), używamy debug panelu:

```typescript
async completeIntakeWithDefaults(timeoutMs: number = 180_000): Promise<void> {
  await this.openDebugPanel();

  // Activate Auto-Fill - system gada sam ze sobą
  const activateButton = this.page.locator('button:has-text("Activate")');
  await activateButton.click();

  // Czekaj na zakończenie (ContinueBar visible)
  await expect(this.continueBar).toBeVisible({ timeout: timeoutMs });

  // Deactivate
  const deactivateButton = this.page.locator('button:has-text("Deactivate")');
  await deactivateButton.click();
}
```
