# 2025-12-25

## Migracja auth: Convex Auth → Clerk

Duża zmiana. Wyrzuciłem `@convex-dev/auth` i przeszedłem na Clerk. Powód: Clerk ma lepsze hosted UI, social login out of the box, i nie wymaga własnej tabeli users/sessions.

### Frontend

`main.tsx` już miał `ClerkProvider` + `ConvexProviderWithClerk` - tylko drobne poprawki.

`App.tsx` - dodałem `<SignIn routing="hash" />` z Clerk. Zastępuje stary custom form.

`SignOutButton.tsx` - zamiana `useAuthActions()` z convex-dev/auth na `useClerk().signOut()`. Proste.

Usunąłem `SignInForm.tsx` - niepotrzebny, Clerk obsługuje UI.

### Backend - główna robota

**Schema** (`schema.ts`):
- Wyrzuciłem `...authTables` - Clerk nie potrzebuje tabel w Convex
- `userId: v.id('users')` → `clerkUserId: v.string()`
- `sessionId: v.id('authSessions')` → `clerkUserId: v.string()`
- Nowe indexy: `by_clerk_user`, `by_clerk_user_action`

**Auth** (`auth.ts`):
- Usunąłem `convexAuth({ providers: [...] })`
- Nowy `loggedInUser` query używa `ctx.auth.getUserIdentity()`
- Zwraca `{ clerkUserId, tokenIdentifier, name, email, pictureUrl }`

**HTTP routes** (`http.ts`):
- Usunąłem `auth.addHttpRoutes(http)` - Clerk sam obsługuje auth routes

**Profiles, sessions, ai.ts, llmLogs, rateLimiter**:
- Wszędzie zamiana `getAuthSessionId(ctx)` na `ctx.auth.getUserIdentity()`
- `identity.subject` to Clerk userId (stabilny across sessions)

### Backwards compatibility

Stare dane w `llmLogs` mają `sessionId` a nie `clerkUserId`. Zrobiłem oba pola opcjonalne w schema na czas migracji. Potem do wyczyszczenia.

### Konfiguracja

Frontend: `VITE_CLERK_PUBLISHABLE_KEY` w `.env.local`
Backend: `CLERK_JWT_ISSUER_DOMAIN` w Convex Dashboard (z Clerk JWT Templates → "convex")

`auth.config.ts` już był skonfigurowany poprawnie.

### Przemyślenia

Clerk upraszcza auth znacząco. Nie muszę zarządzać users/sessions, mam gotowe UI, social login. Trade-off: vendor lock-in, ale dla MVP to ok.

Największa zmiana mentalna: nie ma "session" w sensie Convex Auth. Jest user identity z tokenIdentifier. Dla URL-based session sharing trzeba będzie przemyśleć alternatywę - może custom token mapping do clerkUserId.

85 linii usunięte, auth code znacznie prostszy.
