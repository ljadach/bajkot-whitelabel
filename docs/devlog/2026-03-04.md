# 2026-03-04

## Book pipeline — port z trustee-book-pipeline

Duzy dzien. Port calego pipeline'u generowania spersonalizowanych bajek z zewnetrznego repo do bajkot (Convex + React).

### Co to robi

Rodzic wypelnia formularz (imie dziecka, wiek, problem do przepracowania, wyglad), pipeline przetwarza przez 12 agentow (A0-A11), produkuje spersonalizowana bajke z ilustracjami jako PDF.

Flow: formularz -> walidacja -> profilowanie dziecka (LLM) -> planowanie historii -> pisanie historii -> recenzja psychologiczna (z petla retry A3/A4) -> kierunek artystyczny -> generowanie 2 stylów postaci -> glosowanie rodzica (human-in-the-loop) -> generowanie 7 ilustracji -> QA wizualne -> kompozycja PDF -> QA finalne -> delivery.

Parallel fork po A1: story track (A2-A5) i image track (A6-A6b) rownolegle. Join przez mutation `checkParallelTracksComplete` — sprawdza czy oba tracki skonczyly.

### Architektura

3 tabele: `bookOrders` (zamowienie + status + artefakty jako JSON strings), `bookIllustrations` (7+ obrazow), `bookPrompts` (opcjonalne runtime editing).

Artefakty JSON na `bookOrders` — ten sam wzorzec co `planOutline`/`planFull` na `userProfiles`. Prostsze niz osobna tabela artefaktow.

Kazdy agent to osobny `internalAction`. Chainowanie przez `ctx.scheduler.runAfter(0, ...)`. Separacja: `bookAgents.ts` (`"use node"`) vs `bookPipelineHelpers.ts` (queries/mutations bez node).

### Kluczowe decyzje techniczne

**jsPDF zamiast PDFKit.** PDFKit ma natywne dependencje (canvas, fontkit) ktore w Convex Node.js runtime moga nie dzialac. jsPDF jest pure JS. Trade-off: gorsze wsparcie fontow. Problem: polskie diakrytyki.

**Gemini Imagen przez REST.** OpenRouter nie obsluguje image generation. Bezposredni REST do `gemini-2.5-flash-image`. Rate limiting 2s miedzy callami, retry z backoff. Fallback: 1x1 bialy PNG. Reuse istniejacego `GOOGLE_GENERATIVE_AI_API_KEY`.

**Style vote jako mutation.** Oryginal czekal na Promise z timeout 15 min. W Convex: pipeline ustawia `status: 'style_vote'` i sie zatrzymuje. Frontend reactive query renderuje UI do glosowania. Mutation zapisuje wybor i triggeruje join check. Eleganckie — pipeline nie marnuje zasobow.

**A3/A4 retry loop.** Psych reviewer moze odrzucic historie. Max 3 retry. PASS_WITH_CORRECTIONS: korekty dopisane do tekstu. Po limicie: proceed anyway. Uproszczone vs oryginal ktory mial system original_pl/corrected_pl.

### Frontend

4 route'y, lazy-loaded: `/book/order`, `/book/:orderId/progress`, `/book/:orderId/vote`, `/book/:orderId/result`.

Formularz 5-krokowy z walidacja per step. 16 problemow w 5 kategoriach (leki, emocje, relacje spoleczne, nawyki, zmiany). Mapy wygladu: 6 kolorow wlosow, 8 fryzur, 5 kolorow oczu, 4 odcienie skory, 10 ubran.

Progress page subskrybuje `getOrderProgress` — Convex reactive query, real-time bez SSE.
