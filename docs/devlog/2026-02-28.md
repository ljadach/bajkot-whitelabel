## Co zrobione

Audyt pipeline'u handbook vs obietnice ze stron statycznych wykazał 6 luk. Zaimplementowane poprawki:

- **Mandat na prompt templates** — Chapter 2 wymaga teraz co najmniej jednego kompletnego szablonu z `{{PLACEHOLDERS}}` + para before/after. Word limits zróżnicowane: Ch1 300-450, Ch2 400-700 (najdłuższy), Ch3 300-500.
- **CURRENT KNOWLEDGE** — nowa sekcja w 4 promptach (handbook system x2, playbook system x2) wymuszająca referencje do aktualnych feature'ów narzędzi i datowanie kontekstu.
- **MODULE_HINTS_JSON** — playbook dostaje teraz explicit hints z profilu: excludeTopics (negative prefs), prioritizeNeeds, toolFocus. Wcześniej pole było puste.
- **Editorial guide — Prompt Template Format** — 5-częściowy szablon (Role→Context→Task→Format→Constraints) z przykładem, dodany do editorial guide który idzie do każdego handbook prompt.
- **Style compliance check** — `checkStyleCompliance()` w courseAi.ts sprawdza filler words, forbidden openers, paragraph length. Wyniki logowane do Langfuse span metadata (`style_violations`, `style_compliance_score`). Nigdy nie odrzuca — tylko observability.
- **Sibling modules** — handbook generation dostaje tytuły pozostałych modułów żeby uniknąć powtórek treści między modułami.
- **Exercise type per chapter** — Ch1→reflection, Ch2→prompt_improvement, Ch3→problem_solving. Ćwiczenia dostają pełny profileXml zamiast truncated summary.

## Notatki techniczne

`buildModuleHints()` w profileXml.ts parsuje XML regexem (`<tool name="...">`) — proste i wystarczające dla aktualnego formatu. Gdyby XML się komplikował, trzeba by przejść na prawdziwy parser.

`checkStyleCompliance` ma próg 3 zdań na paragraf (nie 2 jak w guidelines) — luźniejszy żeby uniknąć false positives z code blocks i list items.

Sibling modules helper wyekstrahowany do `buildSiblingModulesSection()` żeby uniknąć duplikacji między `startCourseGeneration` i `regenerateHandbook`.
