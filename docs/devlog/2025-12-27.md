# 2025-12-27

## Course Sneak Preview - nowy krok w flow

Dodany nowy krok "Course Preview" między `plan` a `payment` (payment na razie ukryty).

### Co robi
Dla każdej strony z outline (typowo 5 stron) generuje 3-rozdziałowy "handbook" - personalizowany mini-podręcznik. Generacja równoległa przez `ctx.scheduler.runAfter(0, ...)`, użytkownik widzi real-time status każdego rozdziału.

### Architektura

**Nowa tabela `courseDocuments`:**
- Jeden dokument per strona outline
- Status: pending → generating → completed/failed
- Handbook z 3 rozdziałami (title, content markdown, imagePlaceholder)
- Image placeholder na przyszłość (model: "google-nano-banana")

**Backend:**
- `convex/courseDocuments.ts` - CRUD
- `convex/courseAi.ts` - `startCourseGeneration` (batch) + `generateHandbookInternal` (single)
- `convex/courseAiHelpers.ts` - internal queries dla schedulera
- Nowe prompty `handbook-system` i `handbook-user` w `prompts.ts`

**Frontend:**
- `CoursePreviewStep.tsx` - główny komponent z dwoma widokami:
  - Cockpit: grid kart ze statusem generacji
  - Reader: sidebar z rozdziałami + markdown content
- Komponenty w `src/components/course/`: StatusBadge, CoursePageCard, ChapterNav, HandbookContent, ImagePlaceholder

### UI
- Nawigacja rozdziałów jako sidebar z lewej (styl docs)
- Markdown renderowany przez `react-markdown`
- Manual "Regenerate" button (brak auto-retry)
- Progress bar pokazujący ile stron wygenerowanych

### Zależności
- `react-markdown` - nowa zależność

### Decyzje
- Osobna tabela `courseDocuments` zamiast embeddingu w `userProfiles` - łatwiejsze zarządzanie statusem per dokument
- Równoległa generacja przez scheduler, nie Promise.all - lepsze dla rate limitingu
- Brak resilience (auto-retry) - świadoma decyzja, user ma przycisk regenerate
