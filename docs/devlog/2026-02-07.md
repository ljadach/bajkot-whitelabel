# 2026-02-07 — Video-enhanced lessons: feature flag + corpus integration

## Kontekst

Mamy pipeline: filmy → Gemini analizuje → segmenty → human review → korpus wiedzy. Mamy Cloudflare Stream do serwowania fragmentów. Brakowało: użycie korpusu w generowaniu lekcji + renderowanie wideo w kursie. Krytyczne wymaganie: zero regresji dla obecnych użytkowników.

## Architektura feature flag

Kluczowa decyzja: **PostHog flag per-user, nie globalny ConfigKey na backendzie.**

Pierwsza implementacja używała `ConfigKey.VIDEO_ENHANCED_LESSONS` w Convex — globalnego switcha. Problem: albo włączony dla wszystkich, albo wyłączony. Nie da się targetować pojedynczych test userów.

Finalne rozwiązanie: PostHog feature flag `video-enhanced-lessons` targetowany na email usera. Frontend czyta flagę hookiem `useFeatureFlag()` i przekazuje jako argument `videoEnhanced: boolean` do każdego wywołania backendu. Backend nie ma pojęcia o PostHogu — dostaje bool i wybiera ścieżkę.

Flow:
```
PostHog (per-user) → useFeatureFlag() → videoEnhanced arg → backend if/else → prompts
```

Usunięty `ConfigKey.VIDEO_ENHANCED_LESSONS` z Convex config. Mniej ruchomych części, jedna source of truth na feature flagging.

## Audyt wstecznej kompatybilności

Programowa weryfikacja: 4 produkcyjne prompty (content) **identyczne z main**.

Ścieżka legacy usera (bez PostHog flagi):
- `videoEnhanced` arg = `undefined` → `false`
- Identyczne wywołania `renderPrompt()` co main
- Zero corpus loading
- Zero video markerów w treści
- `HandbookContent` stripuje markery (gdyby jakimś cudem się pojawiły)
- `useQuery(..., 'skip')` — zero zapytań o video stream map

## PostHog flag setup

Flag: `video-enhanced-lessons` (boolean, release toggle)
- Condition: `Email address = equals → cezdmo@gmail.com`
- Rollout: 100% in set
- Verified via Decide API: `video-enhanced-lessons: true`

## Decyzje

- **PostHog per-user > ConfigKey globalny** — jedyna sensowna droga do A/B na produkcji. ConfigKey by wymagał "włącz dla wszystkich albo nikogo".
- **Arg `videoEnhanced` zamiast server-side flag check** — backend nie powinien wiedzieć o PostHogu. Frontend jest source of truth dla feature flags. Backend jest stateless wobec flagowania.
- **Oddzielne prompt template'y zamiast if/else w prompcie** — czytelniejsze, łatwiejsze do zarządzania w Langfuse, zero ryzyka zepsucia produkcyjnego promptu.
- **`v.optional(v.boolean())`** — wstecznie kompatybilne. Stary frontend bez flagi nie przekazuje arg → `undefined` → `false` → legacy path.

## Obserwacja: korpus za cienki na dobre lekcje

Po przetworzeniu 3 filmów (Claude, NotebookLM, Gemini) i zbudowaniu korpusu v2 (172 segmenty) — jakość opisów segmentów jest niewystarczająca do generowania dobrych materiałów edukacyjnych.

Problem: segmenty opisują **akcje użytkownika** ("Clicking the 'Continue with Google' button"), ale nie opisują **kontekstu wizualnego** — co widać na ekranie, jakie opcje są dostępne, jaki jest stan UI, co się dzieje w tle. Przykład:

```
[4:30 - 4:31] Clicking the model selector, currently set to 'Sonnet 4.5'.
```

To za mało żeby LLM napisał tutorial. Potrzebne jest coś w stylu:

```
[4:30 - 4:31] User clicks the model selector dropdown in the top-right corner.
The current model shows "Sonnet 4.5". The dropdown reveals available models:
Opus 4.5, Sonnet 4.5 (selected), Haiku 4.5, with pricing indicators and
capability descriptions next to each option. The chat area behind shows
an empty conversation with suggested prompts.
```

Trzeba wrócić do extraction promptu i dodać instrukcje żeby Gemini opisywał pełny kontekst wizualny — nie tylko co user robi, ale co widzi. To wymaga fundamentalnie innego podejścia do `VideoSegmentExtractionSystem` — narracja wizualna, nie tylko event log.

Odkładamy na osobną sesję. Pipeline działa, mechanika flag jest gotowa, ale content quality wymaga iteracji na prompcie ekstrakcji.
