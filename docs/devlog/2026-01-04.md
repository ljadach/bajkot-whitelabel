# 2026-01-04

## Co zrobiliśmy

Implementacja 3 głównych funkcji enterprise dla AITutor - pełny backend + frontend.

### Feature 1: Interactive Exercises (Gamifikacja)

**Backend:**
- `convex/exercises.ts` - CRUD dla ćwiczeń, submitExercise, getUserPoints, getHint
- `convex/exerciseAi.ts` - evaluateExercise (AI ocena), generateExerciseForChapter (AI generowanie)
- Schema: `exercises`, `exerciseSubmissions`, `userPoints`

**Frontend:**
- `ExercisePanel.tsx` - główny komponent ćwiczenia (prompt, hints, textarea, submit, score+feedback)
- `PointsDisplay.tsx` - badge z punktami w headerze
- Integracja z `HandbookContent.tsx` - ćwiczenie na końcu każdego rozdziału

**Flow:**
1. Handbook się generuje → scheduler uruchamia `generateExerciseForChapter` dla każdego z 3 rozdziałów
2. User czyta rozdział → na dole widzi ćwiczenie
3. Submit → AI ocena (score 0-100) → punkty + feedback
4. Dla istniejących handbooków: przycisk "Generate Exercise"

### Feature 2: Progress Dashboard

**Backend:**
- `convex/progress.ts` - getDashboardStats, getModuleProgress, getActivityOverTime
- Schema: `chapterProgress`, `activityLog`
- Rozszerzenie `userProfiles` o `learningStats` (streaks, time spent)

**Frontend:**
- `ProgressDashboard.tsx` - główna strona dashboardu
- `ProgressChart.tsx` - SVG bar chart aktywności (bez zewnętrznej biblioteki)
- `ModuleCard.tsx` - karta modułu z progress barem
- Route: `/dashboard`

### Feature 3: Team/Manager View

**Backend:**
- `convex/organizations.ts` - createOrganization, inviteMember, acceptInvite, removeMember
- `convex/teamProgress.ts` - getTeamDashboard, getTeamMemberProgress, getTeamLeaderboard
- Schema: `organizations`, `organizationMembers`, `organizationInvites`
- Rozszerzenie `userProfiles` o `organizationId`

**Frontend:**
- `TeamDashboard.tsx` - widok managera z progress całego zespołu
- `MemberTable.tsx` - tabela członków z postępami
- `Leaderboard.tsx` - ranking punktów
- `InviteModal.tsx` - tworzenie zaproszeń (generuje link)
- `JoinOrganization.tsx` - akceptacja zaproszenia przez token
- Routes: `/team`, `/team/invite/:token`

## Obserwacje

1. **Context overflow** - sesja musiała być kontynuowana (summary). Plan mode + duży plan w pliku `.claude/plans/` bardzo pomógł w utrzymaniu kontekstu.

2. **Internal vs public functions** - Convex wymaga rozdzielenia `internalAction/internalMutation` od publicznych. Typy generują się po `convex dev --once`, więc trzeba to robić iteracyjnie.

3. **Scheduler pattern** - Generowanie ćwiczeń w tle przez `ctx.scheduler.runAfter(0, ...)` działa świetnie. Reactive queries automatycznie aktualizują UI gdy dane się pojawią.

4. **Props drilling** - `HandbookContent` potrzebował `courseDocumentId` i `chapterNumber` żeby pokazać `ExercisePanel`. Trzeba było propagować z `PlanStep` i `CoursePreviewStep`.

5. **SVG charts** - `ProgressChart` bez zewnętrznej biblioteki. Prosty bar chart w SVG to ~50 linii kodu. Nie ma sensu ciągnąć recharts/chart.js dla tak prostego przypadku.
