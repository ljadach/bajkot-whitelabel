# **The Editorial Efficiency Engine: Global Style Guide**

## **1\. The Mental Model: Hub and Spoke**

To manage a multi-language platform, we operate on a **Hub and Spoke** architecture.

* **The Hub (Global Core):** The immutable brand DNA. Voice, ethics, and logic that remain consistent across all borders.  
* **The Spokes (Language Derivatives):** Local implementations. These adapt the Hub's energy to specific linguistic rules.

## **2\. Core Philosophy: The Efficiency Mandate**

Our content is a functional tool. Every word must contribute to the "horsepower" of the message.

* **Maximum Accessibility:** Design for universal completion and screen-reader compatibility.  
* **Clarity Over Cleverness:** If a pun or idiom obscures the meaning, delete it.  
* **Intellectual Respect:** Assume the user is intelligent but busy. Do not describe the obvious.  
* **Technical Rigor:** Use precise academic/business terminology (e.g., "Context window") but define it immediately.  
* **Human-Centric SEO:** Write for the human reader first. We believe high-value, high-clarity content naturally optimizes for search engines. Avoid keyword stuffing that increases friction.

## **3\. Voice and Tone: The Senior Partner**

We speak as an expert mentor. We are the **"Guide on the Side,"** not the "Sage on the Stage."

| Context | Primary Subject | Voice / Tone Style |
| :---- | :---- | :---- |
| **Marketing (Static)** | **AITutoro** (3rd) / **We** (Plural) | **Selling the Engine.** Use "AITutoro" for feature capabilities and "We" for mission/authority. |
| **Training (Dynamic)** | **You** (2nd) / **Direct** | **Coaching the Student.** Focus on user action. Use "We" sparingly for hints or nudges. |

## **4\. Structural Mechanics**

* **Sentences:** Short and punchy. Use **Active Voice** only.  
* **Paragraphs:** Generally **1–2 sentences**.  
* **Scannability (The 80/20 Rule):** The reader should extract 80% of value by scanning 20% of text.  
  * **Emphasis:** Use **Bold** text for key takeaways or the "core insight" within a paragraph to anchor the scanner's eye.  
* **Bullet Point Syntax:** \* Always start with a capital letter.  
  * Always end with a period.  
  * Maintain parallel structure (e.g., all bullets start with a verb).

## **5\. Vocabulary Guardrails (The No-Fly List)**

* **No Fillers:** Eliminate "very," "actually," "basically," and "just".  
* **No Shallow Adjectives:** Avoid "cutting-edge" or "world-class."  
* **Concept First Definitions:** Use the precise term, followed immediately by its plain-language meaning.

## **6\. Technical Standards**

### **Brand Orthography**

* **Official Form:** **AITutoro** (No space).

### **Capitalization & Headlines**

* **Case:** Use **Sentence case** for headlines, UI elements, and labels.  
* **Headline Style:** Questions are permitted and encouraged if they mirror the user's internal inquiry (e.g., "What is the thinking model?").

### **Date Formatting**

* **Format:** **Always spell out the month** to avoid international confusion (e.g., "14 October 2024" or "October 14, 2024").  
* **Rationale:** Numeric-only formats (10/12/24) are ambiguous across US and European markets.

### **Context-Dependent Numerals**

* **In Data/Metrics:** Always use Arabic numerals (**15%, 5 units**).  
* **In Instructional Prose:** Spell out small numbers (**one through nine**). Use Arabic numerals for **10 and above**.

## **7\. Interactive Elements (UI Copy)**

### **Links & Anchor Text**

* **Descriptive Only:** Links must describe the destination.  
* **Prohibited:** Never use "click here," "read more," or "link."  
* *Correct:* "Review the \[Chat GPT models\]."

### **Button Logic**

* **Constraint:** Maximum **4 words** per button.  
* **Style:** Verb-first and action-oriented (e.g., "Start next module").

## **8\. Best Practices**

* **The "So What?" Test:** If a sentence doesn't help the user achieve their goal, cut it.  
* **The Mobile Test:** If a paragraph occupies more than 50% of a mobile screen, break it up.  
* **Brand Usage:** Use "AITutoro" when describing the technology; use "We" when discussing the educational philosophy.

## **9\. Code Snippets & Technical Blocks**

Code is a primary learning asset. It must be as scannable and efficient as our prose.

| Feature | Rule |
| :---- | :---- |
| **Language Tagging** | Always specify the language for syntax highlighting (e.g., \`\`\`python). |
| **Comment Strategy** | **Focus on the "Why."** Do not comment on obvious syntax. Adhere to the "Intellectual Respect" rule—assume basics; explain logic. |
| **Snippet Length** | Maximum **20 lines** per snippet. Break long blocks into sub-blocks with prose. |
| **Naming** | Use descriptive, "Plain Language" variable and function names. Avoid cryptic abbreviations. |
| **Indentation** | Consistent 2-space or 4-space standard per language defaults. |

### **Visual Logic for Code**

* **Inline Code:** Use backticks for variables or short commands (e.g., git commit).  
* **Copy-ability:** Every block should imply a "Copy" function; do not include line numbers.  
* **The "Delta" Focus:** Highlight changed lines or use comments like \# Updated logic here.
